# NexVault Release & Auto-Update Guide

## 1. Architecture Overview

NexVault uses a single, deterministic release & update pipeline across **Desktop (`Linux x86_64 AppImage`)**, **Mobile (`Android APK`)**, **Browser Extension**, and **Website**:

1. **Single Version Source of Truth**: Root [`package.json`](package.json) defines the canonical version.
   - Desktop reads `app.getVersion()` from [`apps/desktop/package.json`](apps/desktop/package.json).
   - Mobile injects `__APP_VERSION__` via [`apps/mobile/vite.config.js`](apps/mobile/vite.config.js) and computes `versionCode` / `versionName` directly from [`apps/mobile/package.json`](apps/mobile/package.json) inside [`apps/mobile/android/app/build.gradle`](apps/mobile/android/app/build.gradle).
2. **Measured Release Manifest (`release-info.json` Schema v2)**:
   - Generated by [`scripts/generate-release-manifest.mjs`](scripts/generate-release-manifest.mjs) from the **actual compiled binaries**—never hardcoded.
   - Contains exact byte counts (`size`), human-readable MiB sizes (`sizeFormatted`), `sha256` hex digests, OS requirements, and download URLs.
   - Published alongside `SHA256SUMS.txt` on every GitHub Release and synced to [`apps/website/public/release-info.json`](apps/website/public/release-info.json).
3. **Cryptographically Verified In-App Auto-Updates**:
   - Both Desktop ([`apps/desktop/src/main.js`](apps/desktop/src/main.js)) and Android ([`apps/mobile/src/updater.ts`](apps/mobile/src/updater.ts) + [`AppUpdaterPlugin.java`](apps/mobile/android/app/src/main/java/com/nexvault/app/AppUpdaterPlugin.java)) resolve the latest `release-info.json` manifest (with GitHub REST API fallback).
   - Every redirect hop is restricted to HTTPS `github.com` / `*.githubusercontent.com`.
   - Before executing or installing an update, the updater verifies the exact byte size, SHA-256 digest, and binary format/signature (ELF header on Linux; package name, `versionCode`, and signing certificate on Android).

## 2. Professional Release Workflows

### Standard Local Release (`npm run release`)
Executes the full professional release lifecycle in deterministic order:
1. Pre-flight verification (git working tree clean, semver validity).
2. Runs unit test suite (`npm test`).
3. Bumps version across all workspaces, lockfiles, and manifests.
4. Builds desktop AppImage (`apps/desktop`) and mobile APK (`apps/mobile`).
5. Consolidates binaries into `./release/`, measures real byte sizes and SHA-256 digests, and generates `release/release-info.json` + `SHA256SUMS.txt`.
6. Rebuilds the website with fresh release metadata.
7. Creates atomic git commit `chore(release): vX.Y.Z` and annotated tag `vX.Y.Z`.
8. Pushes branch and tag to GitHub, and uploads release assets if `GITHUB_TOKEN` is present.

```bash
# Standard patch bump (e.g. 0.1.44 -> 0.1.45):
npm run release

# Minor / major / explicit semver:
npm run release -- minor
npm run release -- 0.2.0

# Dry-run preview without writing files or git commits:
npm run release -- --dry-run
```

### Fast CI-Only Release (`npm run release:ci`)
If you prefer GitHub Actions to compile binaries in the cloud:
```bash
# Bumps manifests, runs tests, commits, tags, and pushes:
npm run release:ci
```
Pushing the `vX.Y.Z` tag triggers [`.github/workflows/release.yml`](.github/workflows/release.yml), which builds, signs, checksums, and publishes the release on GitHub.

### Decoupled Platform Releases
Advance Mobile or Desktop independently:
```bash
# Mobile-only bump and build:
npm run release -- --target=mobile

# Desktop-only bump and build:
npm run release -- --target=desktop
```

## 3. Individual Build & Publish Commands

| Command | Purpose |
| :--- | :--- |
| `npm run build:all` | Compiles desktop AppImage, Android APK, generates manifest, and builds website |
| `npm run build:desktop` | Compiles Linux x86_64 AppImage |
| `npm run build:mobile:android` | Builds web app, syncs Capacitor, and compiles Android APK |
| `npm run release:publish` | Copies built binaries to `./release/` and generates measured `release-info.json` |
| `npm run release:upload` | Attaches `./release/` binaries and manifest to the GitHub Release |
| `npm run release:verify` | Verifies that all workspace manifests match the specified release tag |
| `npm run build:website` | Builds the landing website with current release metadata |

## 4. Android Release Keystore Setup (One-Time)

Generate a release signing key (keep the `.keystore` file backed up outside git):

```bash
keytool -genkeypair -v \
  -keystore nexvault-release.keystore \
  -alias nexvault \
  -keyalg RSA -keysize 4096 -validity 10000
```

### For GitHub Actions CI
Add the following repository secrets in **GitHub → Settings → Secrets and variables → Actions**:
- `ANDROID_KEYSTORE_BASE64`: output of `base64 -w0 nexvault-release.keystore`
- `ANDROID_KEYSTORE_PASSWORD`: your keystore password
- `ANDROID_KEY_ALIAS`: `nexvault`
- `ANDROID_KEY_PASSWORD`: your key password (optional if identical to `ANDROID_KEYSTORE_PASSWORD`)
- `VERCEL_DEPLOY_HOOK`: (optional) Vercel Deploy Hook URL to trigger an automatic website rebuild after a release is published

### For Local Signed Builds
Create `apps/mobile/android/keystore.properties` (git-ignored):

```properties
storeFile=/absolute/path/to/nexvault-release.keystore
storePassword=YOUR_PASSWORD
keyAlias=nexvault
keyPassword=YOUR_PASSWORD
```
