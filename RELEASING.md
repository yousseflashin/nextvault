# NexVault Release & Auto-Update Guide

## 1. Architecture Overview

NexVault uses a single, deterministic release & update pipeline across **Desktop (`Linux x86_64 AppImage`)**, **Mobile (`Android APK`)**, **Browser Extension**, and **Website**:

1. **Single Version Source of Truth**: Root [`package.json`](file:///home/youssef/projects/nextvault/package.json) defines the canonical version.
   - Desktop reads `app.getVersion()` from [`apps/desktop/package.json`](file:///home/youssef/projects/nextvault/apps/desktop/package.json).
   - Mobile injects `__APP_VERSION__` via [`apps/mobile/vite.config.js`](file:///home/youssef/projects/nextvault/apps/mobile/vite.config.js) and computes `versionCode` / `versionName` directly from [`apps/mobile/package.json`](file:///home/youssef/projects/nextvault/apps/mobile/package.json) inside [`apps/mobile/android/app/build.gradle`](file:///home/youssef/projects/nextvault/apps/mobile/android/app/build.gradle).
2. **Measured Release Manifest (`release-info.json` Schema v2)**:
   - Generated by [`scripts/generate-release-manifest.mjs`](file:///home/youssef/projects/nextvault/scripts/generate-release-manifest.mjs) from the **actual compiled binaries**—never hardcoded.
   - Contains exact byte counts (`size`), human-readable MiB sizes (`sizeFormatted`), `sha256` hex digests, OS requirements, and download URLs.
   - Published alongside `SHA256SUMS.txt` on every GitHub Release and synced to [`apps/website/public/release-info.json`](file:///home/youssef/projects/nextvault/apps/website/public/release-info.json).
3. **Cryptographically Verified In-App Auto-Updates**:
   - Both Desktop ([`apps/desktop/src/main.js`](file:///home/youssef/projects/nextvault/apps/desktop/src/main.js)) and Android ([`apps/mobile/src/updater.ts`](file:///home/youssef/projects/nextvault/apps/mobile/src/updater.ts) + [`AppUpdaterPlugin.java`](file:///home/youssef/projects/nextvault/apps/mobile/android/app/src/main/java/com/nexvault/app/AppUpdaterPlugin.java)) resolve the latest `release-info.json` manifest (with GitHub REST API fallback).
   - Every redirect hop is restricted to HTTPS `github.com` / `*.githubusercontent.com`.
   - Before executing or installing an update, the updater verifies the exact byte size, SHA-256 digest, and binary format/signature (ELF header on Linux; package name, `versionCode`, and signing certificate on Android).

## 2. One-Command Release (`npm run release`)

```bash
# Patch bump (e.g. 0.1.30 -> 0.1.31), commit, tag, and push to trigger GitHub Actions:
npm run release

# Minor / major / explicit version:
npm run release -- minor
npm run release -- 0.2.0

# Preview without modifying files:
npm run release -- patch --dry-run
```

Pushing a `vX.Y.Z` tag triggers [`.github/workflows/release.yml`](file:///home/youssef/projects/nextvault/.github/workflows/release.yml), which:
1. Verifies all workspace manifests match the tag (`node scripts/release.mjs --verify`) and runs unit tests.
2. Builds the Linux `x86_64` AppImage on `ubuntu-22.04`.
3. Builds and signs the Android release APK (`assembleRelease`) and verifies its signature with `apksigner`.
4. Generates `release-info.json` and `SHA256SUMS.txt` and publishes an atomic GitHub Release.

## 3. Android Release Keystore Setup (One-Time)

Generate a release signing key (keep the `.keystore` file backed up outside git):

```bash
keytool -genkeypair -v \
  -keystore nexvault-release.keystore \
  -alias nexvault \
  -keyalg RSA -keysize 4096 -validity 10000
```

### For GitHub Actions CI
Add the following repository secrets in **GitHub → Settings → Secrets and variables → Actions**:
- `ANDROID_KEYSTORE_BASE64`: output of `base64 -w0 nexvault-release.keystore`
- `ANDROID_KEYSTORE_PASSWORD`: your keystore password
- `ANDROID_KEY_ALIAS`: `nexvault`
- `ANDROID_KEY_PASSWORD`: your key password (optional if identical to `ANDROID_KEYSTORE_PASSWORD`)
- `VERCEL_DEPLOY_HOOK`: (optional) Vercel Deploy Hook URL to trigger an automatic website rebuild after a release is published

### For Local Signed Builds
Create `apps/mobile/android/keystore.properties` (git-ignored):

```properties
storeFile=/absolute/path/to/nexvault-release.keystore
storePassword=YOUR_PASSWORD
keyAlias=nexvault
keyPassword=YOUR_PASSWORD
```
